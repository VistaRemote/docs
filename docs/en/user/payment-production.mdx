# Production payment readiness (ops)

Use this page to walk **mock → sandbox → production**. Lite checkout (commerce **complete** / **status**, plus the Entitlement ingress webhook) can cache local `User.plan`. **WeChat Pay / Alipay merchant onboarding and production PSP secrets are owner-ops — not shipped with VistaRemote.** Never commit merchant secrets.

Architecture: [Commercial billing](/architecture/commercial-billing). Admin modules: [Admin console](/user/admin-console). Spec: `spec/billing-commerce-spec.md`.

## Path: mock → sandbox → production

| Stage | Typical config | Behavior |
| :--- | :--- | :--- |
| **Mock (local)** | `ENTITLEMENT_MODE=off` | Local orders and plans. The order owner may call `POST /api/v1/billing/orders/:id/simulate-paid` (Controller JWT). Admin **Simulate paid** applies only to `source=local_billing`. |
| **Sandbox** | `ENTITLEMENT_MODE=enforce`, central Entitlement reachable | Checkout `POST /api/v1/commerce/orders/:id/pay`: catalog `wechat` → `wechat_pay_v3`, `alipay` → `alipay_f2f`. Sandbox secrets live on **Entitlement**, not this repo. complete / status polling syncs local `User.plan`. |
| **Production** | Same mode + production Entitlement / PSP (owner-ops) | VistaRemote lite webhook `POST /api/v1/commerce/webhooks/entitlement` can sync `User.plan`. **WeChat / Alipay platform notify lands on LuminaryWorks Entitlement**, not VistaRemote. Real merchant onboarding, certificates, and platform callbacks are **not shipped** with this repo. |

Lite ingress requires header `X-Entitlement-Signature` to equal `ENTITLEMENT_WEBHOOK_SECRET` (shared secret, constant-time compare). That is **not** HMAC-SHA256 of the body and **not** WeChat / Alipay platform notify verification.

## VistaRemote server env names (names only)

Names below come from `server` source and `server/.env.example`. **Do not invent values.** Keep production secrets in a secret store / Entitlement host — not in git.

This repo has **no** `COMMERCE_*` environment variables. The commerce BFF forwards `/v1/...` using `ENTITLEMENT_BASE_URL`.

| Name | Role |
| :--- | :--- |
| `ENTITLEMENT_MODE` | `off` \| `shadow` \| `enforce` \| `offline_license` |
| `ENTITLEMENT_BASE_URL` | Central Entitlement base URL |
| `ENTITLEMENT_SERVICE_API_KEY` | M2M `X-Service-Key` |
| `ENTITLEMENT_WEBHOOK_SECRET` | Lite ingress shared secret; empty → webhook **always 401** |
| `ENTITLEMENT_CACHE_TTL_MS` | Entitlement cache TTL |
| `ENTITLEMENT_OFFLINE_GRACE_MS` | Offline grace |
| `ENTITLEMENT_DEPLOYMENT_ID` | Deployment id |
| `ENTITLEMENT_LICENSE_PUBLIC_KEYS` | Offline License public-key JSON (`offline_license`) |
| `ENTITLEMENT_LICENSE_PAYLOAD` | Offline License payload (`offline_license`) |
| `ENTITLEMENT_LICENSE_ALLOW_GRACE` | Offline License grace flag |
| `PRODUCT_CODE` | Product code (example: `vistaremote`) |
| `BILLING_ALLOW_SIMULATE_PAID` | Only when `NODE_ENV=production`: `true` re-enables simulate-paid. Production should **omit it or leave it not true** |
| `NODE_ENV` | `production` disables simulate-paid by default |

WeChat / Alipay **merchant ids, APIv3 keys, certificates, and Alipay app secrets** belong on Entitlement / the PSP — **not** VistaRemote server env vars. `ENTITLEMENT_TRIAL_PURGE_*` is trial recording purge, not a payment callback.

## Checklist

- [ ] **System page flags (FR-WAD-52)**: Admin **System** → entitlement/payment flags. `GET /api/v1/admin/system/entitlement` returns only `entitlementMode`, `entitlementBaseUrlConfigured`, and `webhookSecretConfigured`. It must **not** include `ENTITLEMENT_WEBHOOK_SECRET` or a raw base URL. Use **Copy entitlement status JSON** to confirm.
- [ ] **Reject a bad signature**: `POST /api/v1/commerce/webhooks/entitlement` with a wrong or missing `X-Entitlement-Signature` must return **401** `ENTITLEMENT_WEBHOOK_UNAUTHORIZED` and must not change local `User.plan`. Unset secret → **401** as well.
- [ ] **simulate-paid forbidden for commerce**: `POST /api/v1/admin/orders/:id/simulate-paid` on `source=commerce` returns **400** `COMMERCE_SIMULATE_PAID_FORBIDDEN`. Do not call `POST /api/v1/billing/orders/:id/simulate-paid` with an Admin JWT.
- [ ] **Disable simulate-paid in production**: when `NODE_ENV=production` and `BILLING_ALLOW_SIMULATE_PAID` is not `true`, simulate-paid returns **400** `SIMULATE_PAID_DISABLED`.
- [ ] **Grant path**: after sandbox commerce **pay** + **complete** / **status** (or a lite webhook paid/fulfilled payload), the Admin **Users** list shows the matching `plan`. That is a local cache, not proof that production PSP settlement is complete.
- [ ] **No secrets in git**: `.env`, CI logs, and Admin JSON must not contain merchant secrets.

## Not shipped (owner-ops)

Complete these on the **LuminaryWorks Entitlement / PSP consoles**. VistaRemote does **not** accept WeChat / Alipay platform notify; this repo only has lite `POST /api/v1/commerce/webhooks/entitlement`. No production merchant pack ships with VistaRemote:

- WeChat merchant onboarding, APIv3 key and platform certs, payment notify URL **on Entitlement**
- Alipay app and keys, face-to-face / sandbox → production cutover
- Production credentials for PayPal / Wise and other channels
- Store those secrets in the **Entitlement** environment (do not commit them in `server/.env`)

After onboarding, re-run this checklist: System flags, bad-signature 401, and commerce simulate-paid still forbidden.

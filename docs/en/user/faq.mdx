# FAQ (Users)

## Pairing & connection

**Invalid pairing code?**  
It may have expired (~5 minutes by default), been mistyped, or already consumed (`PAIRING_CONSUMED` — a class cannot share one code); regenerate on the host.

**Video works but no control?**  
Confirm the host Agent clicked **Allow**, and pairing was not **View only**. The control channel may also be missing. Mouse/keyboard inject exists on Windows and macOS. Refresh the session or check Agent version with IT.

**Stuck on connecting?**  
Check network/firewall UDP and whether TURN is configured.

**Is VistaRemote MeshCentral?**  
No. Logged-in session tools (screen, input, files, terminal, and so on) are in VistaRemote. Mesh RMM such as AMT, registry, remote print, and Wake-on-LAN is not. See the mapping in [Remote control](/user/remote-control).

## Privacy & AI

**Is data sent to OpenAI by default?**  
Default private deployment uses **Ollama + self-hosted vector DB**; cloud inference only when enabled and entitled.

**What does Desktop AI do?**  
Local rules/light inference for behavior hints; heavy jobs go to the `ai` worker queue.

## Admin & remote ops

**How do I force-disconnect a session?**  
Open the [Admin console](/user/admin-console) → **Sessions** and **force disconnect** the active room. The server closes the signaling WebSocket first, then clears the in-memory room. The host can also disconnect from the always-on-top connection bar; see [Remote control](/user/remote-control). Disabling a user does not kick an in-progress session — still disconnect it under Sessions.

**When is a device “online”? What are labels?**  
**Online** means the device’s last heartbeat was within about **120 seconds**; after that it is offline. Online is not “currently sharing the screen.” On **Devices** you can edit **labels** and filter by them. Revoking a device makes the next heartbeat fail; that is separate from the online check. See [Admin console](/user/admin-console).

**How does recording playback work? Is it a MinIO player?**  
No. In 1.11.0, playback is a **local browser `<video>`** on the Recordings page (seek / speed), not a MinIO product player. Agent MediaRecorder capture and MinIO chunk upload are not shipped; the list is metadata — do not accept a cloud object player.

**ICE stuck — should I change DNS?**  
Do not start by changing DNS. On Admin **System**, run the **ICE probe** (browser STUN gather) and check whether STUN candidates appear. After the probe, you can copy the probe result / STUN URL for tickets. If it still fails, check UDP/firewall and TURN; see [Remote control](/user/remote-control) connection quality. ICE servers come from the Server; secrets on the System page are masked.

**Can I edit the permission matrix?**  
No. The Permissions page is a **read-only** map of platform RBAC / org roles. **ADM-2** (editable role bindings) is not shipped; do not accept an editable matrix. See [Admin console](/user/admin-console).

**How do Admin CSV exports work?**  
They export the **currently filtered/loaded list** (client-side unless the page says otherwise; audit CSV is server-filtered, including result). Users, devices, security, jobs, orders, orgs, and recordings have CSV buttons where implemented; the org drawer **SupportGrant** table also has **export grants CSV** (1.33.0). This is not a full warehouse dump, and not a billing/payment export. See [Admin console](/user/admin-console).

**Can I open overview cards and list filters from a URL?**  
Yes. Overview metric cards and most list filters support **URL query seeds** (for example `/devices?online=offline`, `/users?planExpiry=expired`, `/audit?result=denied`, `/recordings?status=failed`). Permission matrix search is a read-only filter, not editable roles. See [Admin console](/user/admin-console).

**How do security mute rules work?**  
On [Admin console](/user/admin-console) → **Security events**, configure muted types (alert rules lite). The list applies saved rules by default (Switch **Apply mute rules**); turn it off or open `?applyMute=false` to see all types. The high-severity banner count still excludes muted types.

**Where is SupportGrant managed? Does revoke kick sessions?**  
In the organization drawer: create / list / revoke **SupportGrant** temporary IT-assist grants, and **export grants CSV** (current filter/loaded rows). The revoke confirmation can check **Revoke and disconnect related sessions** (`?kickSessions=true`, off by default). The permission matrix stays read-only. See [Admin console](/user/admin-console).

**What are the System page entitlement flags?**  
The **System** page shows read-only flags such as `entitlementMode`, `entitlementBaseUrlConfigured`, and `webhookSecretConfigured` — **no secrets** or webhook secret values. You can **copy entitlement status JSON** (those flags only, 1.33.0). Use it to verify Entitlement configuration, not to change plans. See [Admin console](/user/admin-console).

**Recording playback URL expired? MinIO EntityTooSmall?**  
The Recordings player fetches a short-lived signed **playback-url** (`expiresAt`; refresh on expiry). When `failedReason` matches **EntityTooSmall / part size**, the list shows a hint that the Agent should coalesce non-final parts to **≥5 MiB** (Desktop ≥1.30; `memory://` still allows small parts). See [Admin console](/user/admin-console).

**Monitor wall vs full SFU wall?**  
Today you get a 2×2 shell with slot **in-wall observe** (single-stream embed, FR-WAD-72 MVP) — **not** a full cross-session SFU multi-stream wall. That is **FR-WAD-108** (Spec drafted; implementation open; depends on SFU multi-producer + MD-4). Do not accept it as shipped. See [Admin console](/user/admin-console).

**What does the observe ticket return (1.36.0)?**  
`POST /admin/rooms/:roomId/observe` returns the shared **AdminObserveTicket** DTO (`signalingTicket`, `role: observe`, …). SFU fields (`routerId`, `transport`, `consumer`) are **null stubs** — not mediasoup handshake yet.

**Does the monitor wall layout save automatically?**  
No. URL **`s0`–`s3`** take priority; without seeds the page restores from **GET** `/admin/monitor-wall/layout`; click **Save layout** (**PUT**, **admin.write**) to persist. See [Admin console](/user/admin-console).

**How do I open a recording from a summarize job (1.37.0)?**  
On **Jobs**, `recording.summarize` rows with id `summarize-{recordingId}` show **Recording** in **Actions** → `/recordings?recordingId=…`. Job filters (`id`, `name`, `state`, `failedReason`) sync to the URL; overview **failed jobs** opens `/jobs?state=failed`.

**How do efficiency reports open the recordings list (1.37.0)?**  
On **Efficiency reports**, click **Open recordings** — it carries active `userId` / `sessionId` / `deviceId` / `recordingId` substring filters to `/recordings` (rollup period is not passed; filters only).

**Audit layout rows and monitor wall (1.37.0 / 1.38.0)?**  
Filter audit by **monitor-wall layout** (`admin.monitor_wall.layout`). **1.38.0** — **Save layout** audit meta includes **`roomIds`** and the first **`roomId`**. Matching rows show **Monitor wall** — `/monitor-wall` or `/monitor-wall?s0=<roomId>` from meta / resource / target `roomId` / `room_id`. Slot 0 seed only; **not** SFU multi-stream shipped. See [Admin console](/user/admin-console).

**How do user drawer related links work (1.38.0)?**  
On **Users**, open the detail drawer and click **View sessions / recordings / orders / devices / audit** — they open `/sessions?userId=…`, `/recordings?userId=…`, `/orders?userId=…`, `/devices?ownerId=…`, and `/audit?actorId=…`. See [Admin console](/user/admin-console).

**How do I jump to the monitor wall from an active device session (1.38.0)?**  
On **Devices**, when a row has an active session, **Actions** shows **Monitor wall** → `/monitor-wall?s0=<sessionId>`. Slot 0 seed only — does **not** start SFU multi-stream or in-wall observe. See [Admin console](/user/admin-console).

**How do I filter sessions by user ID (1.38.0)?**  
On **Sessions**, filter by **user ID**; the filter syncs to **`?userId=`** in the URL (the user drawer **View sessions** button seeds this param). See [Admin console](/user/admin-console).

**Where do I see recent pairing codes (1.39.0)?**  
Open [Admin console](/user/admin-console) → **Operations** → **Pairings** (`/pairings`). The page loads **GET** `/api/v1/admin/pairings` (requires **admin.read**) and lists recent codes from PostgreSQL (default **100** rows; optional **`limit`** 1–500). Filter by device ID, owner user ID, or numeric code — filters sync to **`?deviceId=`**, **`?userId=`**, **`?numericCode=`**. Row **Device** / **User** links open `/devices?deviceId=` and `/users?userId=` (device owner). Read-only — change length/TTL under **System** pairing policy; hosts generate codes on the Agent. See [Admin console](/user/admin-console).

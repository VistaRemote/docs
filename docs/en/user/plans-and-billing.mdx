# Plans & Billing (Users)

## Plan overview

| Plan | For |
| :--- | :--- |
| **Free / trial** | Personal or non-commercial; time-limited premium trial |
| **Pro** | Small teams; SFU multi-viewer, cloud AI inference, etc. |
| **Enterprise** | Audit, policies, self-hosted, **device fleet** (group control / monitor wall / virtual display, etc.), dedicated support |

Canonical description: [Commercial trial](/architecture/commercial-trial).

## Enterprise device fleet

After purchasing enterprise service (see [Device Fleet & Enterprise](/user/fleet-and-enterprise)):

| Capability | Notes |
| :--- | :--- |
| **Group keyboard & mouse** | One controller operates many authorized devices |
| **Batch commands** | Notify, lock, reboot, open URL, and more |
| **Multi-screen monitor wall** | Thumbnail observe, click-up to HD control; larger slots as contract add-on |
| **Virtual display** | Dedicated virtual screen for remote sessions |
| **Out-of-band (AMT, etc.)** | Enabled under enterprise private-deploy contracts |

Enabled after you buy enterprise service. Larger monitor-wall slots and on-site scope are in the contract. See [Device fleet and enterprise](/user/fleet-and-enterprise).

## After trial ends

These typically require a **paid plan**:

- **Many viewers** on one shared desktop
- **Cloud behavior analysis**
- **Cloud recording and playback** (buffered on the host computer, then uploaded; this does not use the multi-viewer path’s recorder)

## Recording & plans

| Capability | Plan | Notes |
| :--- | :--- | :--- |
| Agent-side recording + cloud storage | Pro and above | Buffered on the host, then uploaded in parts. Not the default recorder on the multi-viewer path |
| Central recording | Enterprise | Recorded on the forwarding service. Higher resource use, enabled on its own |

See [Recording & billing](/architecture/recording-and-billing).

## Purchase options

- **Subscription**: monthly/yearly renewal
- **Perpetual**: one-time license (per product catalog)

Payment methods follow the deployment: WeChat Pay, Alipay, PayPal, Wise, and bank card.

## Upgrade and renewal

1. Sign in on the web client, or ask sales for a payment link.
2. The plan applies after payment. An admin can also change a user’s plan in the console.
3. Renew before expiry so multi-viewer sessions and cloud analysis continue.

## Membership page

On the web client membership page, choose WeChat Pay or Alipay and pay with the QR code or payment link. The page waits for the result. You can also choose complete payment to refresh the plan. Past orders are in the admin console. The membership page does not link there.

## For operators

- Production payment callbacks land on Entitlement. Check [Production payment readiness](/user/payment-production) before go-live.
- In a local or sandbox environment, the membership page polls the order. Admin can mark a **local order** paid so the plan turns on. That does not replace a live merchant notification.
- The screen shows channel names such as WeChat and Alipay. Do not show internal provider ids to end users.

Integrators: [Commercial billing](/architecture/commercial-billing).

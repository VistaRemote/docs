## 1. Three one-liners

**VistaRemote** is WebRTC remote control of an already logged-in desktop, plus a **device fleet**: group control, batch commands, multi-screen monitor wall, virtual display, and more. Signaling is NestJS; media is P2P / TURN / mediasoup; state can stay in your PostgreSQL. Fleet capabilities are **Enterprise** scope and enabled after purchase. With VistaCast: Cast watches business video; Remote manages Edge boxes.

**BilldDesk** is a ToDesk-style remote desktop. The [open-source repo](https://github.com/galaxy-s10/billd-desk) is not a stable release; Pro source is not public. The “open source” column follows the cloned source.

**MeshCentral** is self-hosted machine management with a server relay to MeshAgent (remote desktop is not WebRTC by default), plus terminal, files, device ACL, audit, and Intel AMT.

See [Positioning](./positioning) and [Device Fleet & Enterprise](/user/fleet-and-enterprise).

## 3. Stack differences (for technical buyers)

| | VistaRemote | BilldDesk open source | MeshCentral |
| :--- | :--- | :--- | :--- |
| HTTP | NestJS + **Fastify** | Koa2 | Express |
| Database | **PostgreSQL** + TypeORM | MySQL | NeDB by default |
| Media | WebRTC (P2P / TURN / SFU) | WebRTC | Often server relay |
| Desktop | Electron | Electron + nut.js | MeshAgent |
| UI | React + Rsbuild | Vue 3 | Handlebars |

We align on product capabilities, not on copying another stack.

## 4. How to talk to enterprise buyers

Group control, monitor wall, virtual display, and OOB are **in product scope**, enabled with **Enterprise**, and delivered on a **contract schedule** when needed. Customer docs do not use internal engineering stage language. Details: [Device Fleet & Enterprise](/user/fleet-and-enterprise).

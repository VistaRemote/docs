## 1. Three one-liners

**VistaRemote** is remote control of an already logged-in desktop. Signaling is NestJS. Media is WebRTC (P2P, TURN, or mediasoup). State can stay in your own PostgreSQL.

**BilldDesk** is a ToDesk-style remote desktop. The [open-source repo](https://github.com/galaxy-s10/billd-desk) is not a stable release; the author says permission and input problems are not fixable on that architecture. Pro is a rewrite and its source is not public. The “open source” column below follows the cloned source, not the README checklist.

**MeshCentral** is self-hosted machine management. The browser reaches MeshAgent through a server relay. Remote desktop is not WebRTC by default. It also covers terminal, files, device-group ACL, audit, and Intel AMT.

Broader positioning (legacy monitoring vs commercial monitoring) stays in [Positioning](./positioning). This page only compares remote-desktop and RMM products.

## 3. Copy capabilities, not stacks

| | VistaRemote (kept) | BilldDesk open source | MeshCentral |
| :--- | :--- | :--- | :--- |
| HTTP | NestJS + **Fastify** | Koa2 | Express |
| Database | **PostgreSQL** + TypeORM, UUIDv7 keys | MySQL + Sequelize | NeDB by default |
| Realtime | Own WebSocket signaling; media is WebRTC | Socket.io rooms | Own WebSocket; server relays bytes |
| Desktop | Electron + existing injectors (no nut.js) | Electron + nut.js | Prebuilt MeshAgent |
| UI | React + Rsbuild + Sass Modules | Vue 3 | Handlebars |

Do not import live-room models, Socket.io, Mesh JPEG relay, or AMT into VistaRemote. The Pro author already says the open-source architecture cannot fix permission and control, so only product capabilities are aligned.

---

## 4. Why this wave stops

Out-of-band management (AMT), the registry, service start/stop, and login-window injection would turn the product into a different RMM and break the logged-in-session boundary. Group control, virtual displays, and driver-level input wait for their own requirements. They are not claimed as done here.

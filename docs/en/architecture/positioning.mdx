# Positioning & Advantages

## One-liner

**Open-source, self-hostable** remote desktop and monitoring: **WebRTC** for real-time control, **private AI** for recording insights — data stays on your infrastructure.

**When you do not need tens of millions of concurrent viewers**, VistaRemote is often the **best trade-off**: fast delivery, low customization cost, full-stack **TypeScript** (+ **Python** only for heavy ML).

## vs traditional monitoring

| | Legacy DVR-style tools | VistaRemote |
| :--- | :--- | :--- |
| Transport | Proprietary TCP | **WebRTC** |
| Real-time control | Weak | **Strong** |
| Playback | Main-thread decode | **WebCodecs** + Worker |
| AI | Vendor cloud | **Self-hosted `ai` + Ollama** |
| Customization | C++/closed | **TS + Spec + `shared`** |

## Why not Flutter

Flutter’s Skia/Impeller pitch targets **self-drawn UI** frame rates. VistaRemote bottlenecks are **WebRTC and OS APIs** (DXGI capture, NVENC, global input hooks)—**Rust** via N-API/JSI, not Dart. UI stays **React + Rsbuild** (Web/Desktop) and **React Native + JSI** (mobile). Rspack’s Rust implementation speeds **bundling**, not a reason to adopt Flutter for runtime UI.

## Development velocity

- **TypeScript** across server, web, desktop, mobile; **Python** in `ai/python-worker` only.
- **Meta-Repo** (not monorepo): isolated native stacks, **sub-second** Rsbuild cold start, lightweight CI.
- **PostgreSQL + Docker** — familiar ops in CN/EU SMB.
- See [Customization](/guide/customization).

## Edge AI vs legacy remote tools

Legacy stacks struggle to embed **PaddleOCR-slim + edge Qwen2.5-VL + rules**. VistaRemote treats AI as a first-class pipeline in TS (`desktop/edge-ai`, `ai`).

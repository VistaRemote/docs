# 二开与定制：为什么选择 VistaRemote

选 VistaRemote 做二次开发，是因为 **改得动、招得到人、数据留在自己的机房**。它面向企业内网和行业定制，而不是千万级观众的直播。

## 选择它做二开的理由

| 理由 | 对你的团队意味着什么 |
| :--- | :--- |
| **一种主语言** | 信令、Web 主控、管理台、Electron Agent、手机主控、AI 任务都是 **TypeScript**。招 Node / React 工程师就能改产品，不必同时养 C++ 远控团队 |
| **契约只有一处** | 跨端类型在 `shared`。改协议先改契约，Web、桌面、手机不会各写一套字段 |
| **Spec 驱动** | 行为写在 Spec 里再写代码。人和 AI 协作者对着同一份说明改，评审时也能对照 |
| **仓库分开、构建不互相拖死** | Electron、React Native、NestJS 各自独立。只拉要改的子仓，Rsbuild 冷启动快 |
| **运维你已经会** | **PostgreSQL + Docker**。单机可以拉起信令、数据库、录制和 AI |
| **重计算不污染主业务** | OCR、视觉等重活在 `ai` 的 Python worker。主路径仍是 TypeScript |
| **插件，而不是只能分叉全仓** | 行业规则、额外管理页、对接 IM，可以按插件清单扩展，不必把上游远控逻辑改散 |

语言本身简单、生态成熟。小团队可以在数周内做完企业常见定制，例如：

- 企业 **SSO / OIDC** 登录
- 远程协助前的 **审批流**
- 按行业改的 **管理台** 字段和报表
- 内网 **OCR / 视觉** 规则（数据不出域）
- 会话事件推到企业微信、钉钉或自有工单

## 和闭源远控、老 C++ 项目比

| | VistaRemote | 闭源商业远控 | 传统 C/C++ 开源远控 |
| :--- | :--- | :--- | :--- |
| 改界面和管理台 | 改 React 页面 | 通常不能改 | 往往要动原生 UI |
| 改协议 | 改 `shared` 后各端一起编过 | 不能改 | 多语言绑定容易漂移 |
| 招人 | 国内 TypeScript 人才多 | 只能等厂商排期 | C++ 桌面 + 自有协议，周期长 |
| 数据位置 | 自建 PostgreSQL、MinIO、Ollama | 常在厂商云 | 看你怎么部署 |
| AI | 独立服务，可完全内网 | 多绑定厂商模型 | 通常没有 |

## 推荐改动顺序

```text
1. 读产品定位和相关模块 Spec
2. 若动协议，先改 shared
3. 改 server API 或管理台
4. 改 Web 主控或 Desktop Agent
5. 用户能看见的行为，同步文档
```

## 适合谁

适合：**企业内网、会话规模在万级以内、要掌握数据、要改代码** 的客户。

不适合：全球亿级观众同屏直播，或明确要求闭源黑盒、拒绝自建的采购。

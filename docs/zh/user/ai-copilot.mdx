# AI 协助（Windows / macOS 电脑操控）

AI 协助默认关闭。打开之后，你可以在 Viewer 里用一句话，让本组织的 AI 在**被控 Windows 或 macOS** 上已经打开的窗口里点击和输入，包括浏览器。

能力对标开源社区的 **[Windows-MCP](https://github.com/CursorTouch/Windows-MCP)** 与 **MacOS-MCP** 一类「看屏幕 → 点击 / 输入」computer-use 工具面。VistaRemote **不把**这些程序打进安装包。默认仍把允许的动作接到已有 WebRTC DataChannel，让 AI 与人工远控走同一条链路。只有被控端另外打开平台 MCP 时，才会在本机 stdio 拉起 `windows-mcp` 或 `macos-mcp`；拉起失败就回到原来的键鼠注入。

这不是无人值守接管，也不包含脚本、注册表或文件代写。

## 为什么这是核心能力

| 维度 | VistaRemote AI 协助 | 典型桌面 MCP（Windows-MCP / MacOS-MCP） |
| :--- | :--- | :--- |
| 目标系统 | 远端 Windows / macOS Agent | 本机桌面 |
| 工具面 | 截屏观察、Click、Type、滚动等有界动作 | 同类 look → click/type |
| 传输 | 已建立的远控会话 + 组织内 AI Worker | 本机 MCP 宿主 |
| 同意 | 人工远控允许之外，还需二次「允许 AI」 | 本机信任模型 |
| 默认 | 关；告警不会自动开控 | 由宿主决定 |

适合：跨地域协助同事点开配置页、在对方浏览器里填表、引导排障——而不是在 Viewer 里替你写脚本改注册表。

## 开始之前

1. 被控电脑已经装好 Agent（Windows 或 macOS），并且你们已经连上同一台会话。
2. 被控端先点「允许」，这只表示允许人工键鼠。
3. 若这台 Agent 打开了 AI 协助，被控端还会看到另一次确认。点「允许 AI」之后，主控工具栏才会出现 **AI 协助**。没点的话，AI 不会动键鼠。
4. 画面缩图会送到你们自己的 AI 服务，用来决定下一步点哪里。默认不会为了这个功能去接公网模型。

## 怎么用

1. 在 Viewer 工具栏打开 **AI 协助**（人类聊天还是原来的入口）。
2. 写下要做的事，例如「点一下浏览器地址栏」。空着不能开始。
3. 步骤里只显示工具名，例如 Click、Type。
4. 点 **停止**，或直接动鼠标、键盘，AI 会暂停。之后你的键鼠和以前一样。

单次任务大约不超过 20 步或 3 分钟。

## 本机 AI（Cursor / ChatGPT）

本机 MCP 只能操作你**已经加入**、且对方已允许 AI 的会话，不能新开远控。服务端开关没开时，工具返回 `COPILOT_DISABLED`。

ChatGPT 桌面版如果能启动同一个本地 stdio MCP，用同一条命令。不要把真实票据写进仓库。示例文件是 `tooling/mcp/cursor-mcp.example.json`：

```json
{
  "mcpServers": {
    "vista-remote": {
      "command": "node",
      "args": [
        "tooling/mcp/vista-remote-mcp.mjs"
      ],
      "env": {
        "VR_API_URL": "http://127.0.0.1:3000",
        "VR_SIGNALING_TICKET": "<signaling-ticket-for-an-existing-session>",
        "VR_SESSION_ID": "<session-id>"
      }
    }
  }
}
```

工具是 `vr_snapshot`、`vr_click`、`vr_type`、`vr_scroll`、`vr_move`、`vr_shortcut`、`vr_wait`。这里没有 PowerShell、Shell，也没有生态里那个只做确认链接的 `remote_control`。

## 还没做到的

- 真机点击是否到位，还需要你在 Windows 或 macOS 上亲眼看一次。文档不把这一版写成已经签收的生产功能。
- 不操作锁屏、注销，也不跑 PowerShell、终端脚本或改注册表。
- 监控告警不会因此自动连上别人的电脑。
- 不会把同一次 AI 操作广播到多台机器。

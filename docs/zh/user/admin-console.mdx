## 常见操作

### 为用户开通 Pro

1. 封闭试用首选：管理台 **用户** → 改套餐（立即写本地 `User.plan`）。
2. Sandbox 收银：用户打开 Web **用户端** `/membership`，选 `providerHint`（微信/支付宝），支付后等待轮询或点 **完成支付**。这不是生产商户 notify。
3. 仅本地 pending 单：管理台 **订单**「模拟支付」（`POST /api/v1/admin/orders/:id/simulate-paid`）。订单所有者也可用 Controller JWT 打 `/api/v1/billing/orders/:id/simulate-paid`。commerce 单会 `COMMERCE_SIMULATE_PAID_FORBIDDEN`。
4. 用户刷新客户端或重新登录后权益生效。

### 禁用用户

1. 用户列表 → 选择用户 → 禁用。
2. 该用户无法新建远程会话。进行中的会话请到「会话」执行 **强制断开**。

### 监控墙布局

**产品能力（Enterprise）**：多路设备缩略图观察，发现异常后点选切入高质量远控；更大槽位可按企业合同加购与验收。详见 [设备舰队与企业能力](/user/fleet-and-enterprise)。

**运维操作摘录：**

1. 打开 **/monitor-wall**，将活跃会话绑定到槽位。  
2. 使用 **保存布局**（须 **admin.write**）持久化绑定。  
3. URL 可用 `s0`–`s3` 等种子预填槽位。  
4. 点选 live 槽可进入控制会话（须企业墙 / 远控权益）。  

（版本演进与 API 细节仍见下文历史说明，供实施同学查阅。）

**布局持久化（1.35.0）** — 持久化槽位与会话绑定。

1. 打开 **/monitor-wall**。URL 查询 **`s0`–`s3`**（兼容 `slot0`–`slot3`）若带有会话 ID，**优先**填充对应槽位，**不会**被已保存布局覆盖。
2. **无** URL 种子时，页面 **GET** `/admin/monitor-wall/layout` 恢复上次保存的槽位绑定。
3. 调整槽位后须点 **保存布局**，才会 **PUT** 同一接口持久化（须 **admin.write**；只读管理员按钮禁用）。保存布局 **不会**自动发起墙内旁观或 SFU 连接。
4. 各槽可开启 **墙内旁观**（缩略图观察）；需要高质量远控时点选进入控制会话。企业多屏监控墙能力与槽位规模见 [设备舰队与企业能力](/user/fleet-and-enterprise)。
5. **1.36.0** — `POST /admin/rooms/:roomId/observe` 返回 shared **AdminObserveTicket**（`signalingTicket`、`role: observe`、`expiresAt` 等）。SFU 观察参数由服务端下发。
6. **1.37.0** / **1.38.0** — 审计动作预设选 **监控墙 layout**（`admin.monitor_wall.layout`）。**1.38.0** 起 **保存布局** 写审计时 meta 含 **`roomIds`**（已绑定槽位的会话 ID 列表）及首个 **`roomId`**。匹配行 **关联** 列 **监控墙** → `/monitor-wall`，或 `/monitor-wall?s0=<roomId>`（meta / resource / target 的 `roomId` / `room_id`）。仅填充槽位 0 种子；需要时在墙上发起旁观。
7. **1.44.0** — 页面提示布局可保存，以及墙内旁观 / 企业多屏观察的使用说明。

### 任务、报告与录制（1.37.0）

1. **任务** — 列表筛（`id`、`name`、`state`、`failedReason`）搜索后与 **URL 同步**（可分享链接；概览「失败任务」打开 `/jobs?state=failed`）。
2. **录制摘要任务** — 类型 `recording.summarize` 且 id 为 `summarize-{recordingId}` 的行，**操作** 列有 **录制**，链到 `/recordings?recordingId=…`（其他任务类型无此跳转）。
3. **效率报告** — **打开录制列表** 打开 `/recordings`，携带当前子串筛（`userId`、`sessionId`、`deviceId`、`recordingId`）；无筛时打开全列表。

### 配对列表（1.39.0 / 1.40.0 / 1.41.0）

**FR-WAD-109** — 近期配对码只读运维视图；**不是**发码器，也与监控墙无关。

1. 打开 **/pairings**（侧栏 **运营管理** → **配对**，在 **设备** 与 **订单** 之间）；从 **概览** → **配对** NavCard（**1.41.0**）；从 **设备** → **操作** → **配对**（预填 `?deviceId=`，**1.41.0**）；或从 **系统** 页 **配对策略** 区点 **打开配对**（**1.40.0**）。
2. 页面调用 **GET** `/api/v1/admin/pairings`（须 **admin.read**）。默认返回最近 **100** 条；可选 **`limit`** 夹在 **1–500**。
3. 服务端筛：**`deviceId`**、**`numericCode`**（子串、不区分大小写）；**`userId`** 按设备表解析的 **owner** 子串匹配；**`consumed`**（**1.41.0**）— **`yes`** = 有 `consumedAt`（已使用），**`no`** = `consumedAt` 为空（未使用）；未知值忽略。
4. 搜索框与 **`?deviceId=`**、**`?userId=`**、**`?numericCode=`**、**`?consumed=yes|no`** URL 同步（可分享链接）。**已消费** 下拉可选 **已消费** / **未使用** / **全部**。
5. 列含配对码、**deviceId**、**userId**（owner）、**sessionId**、**expiresAt**、**consumedAt**。**操作** 列 **设备** → `/devices?deviceId=…`；**用户** → `/users?userId=…`（已知 owner 时）；**会话** → `/sessions?sessionId=…`（**1.40.0**，行有 **sessionId** 时；会话筛与 **`?sessionId=`** URL 同步）。
6. 改码长或 TTL 请到 **系统** 配对策略；被控端仍在 Agent 上生成配对码。
7. **1.44.0** — 页头 **创建审计** / **加入审计** 分别打开 `/audit?action=pairing.create`、`pairing.join`（与 **1.43.0** 审计动作预设相同）。

### 用户抽屉与跨模块深链（1.38.0 / 1.42.0）

1. **用户** — 详情抽屉内 **查看会话 / 录制 / 配对 / 订单 / 设备 / 审计** 分别深链到 `/sessions?userId=…`、`/recordings?userId=…`、`/pairings?userId=…`（**1.42.0**；按设备 **owner** 子串筛配对列表）、`/orders?userId=…`、`/devices?ownerId=…`、`/audit?actorId=…`（设备列表按 `ownerId`；抽屉内设备区仍按 owner / org 逻辑展示）。
2. **设备** — 行关联 **活跃会话**（与内存房间匹配）时，**操作** 列 **监控墙** → `/monitor-wall?s0=<sessionId>`（槽位 0 种子；**不是** SFU 多路已交付）。
3. **会话** — 可按 **用户 ID** 筛选；筛选项与 **`?userId=`** URL 同步（用户抽屉「查看会话」会种子此参数）。客户端按行 `userId` 过滤（行无 `userId` 时不匹配）。

### 会员与订单（1.42.0 / 1.43.0 / 1.52.0）

1. **收银** — Web **用户端** `/membership`（当前 viewer Admin **无会员路由**）：`providerHint`、QR/跳转、支付后轮询 status，并可 **完成支付**（`complete`）。沙箱文案不是生产 PSP。
2. **订单** — 管理台 **订单** 看本地单；「模拟支付」仅 `local_billing` pending。commerce 请结合用户端 Membership 理解。历史 Admin 会员↔订单深链在当前 viewer **未挂**。
3. **开通** — 试用用户卡住 Free 时，优先 **用户** 改套餐，不要对 commerce 单点模拟支付。

## 企业开通与合同范围

以下能力归属企业舰队 / 合同范围（详见 [设备舰队与企业能力](/user/fleet-and-enterprise)），按开通与合同交付：

## 支付与 Entitlement（mock → sandbox）

| 模式 | 行为 |
| :--- | :--- |
| `ENTITLEMENT_MODE=off`（默认） | 本地套餐/订单；不访问中央 Entitlement |
| `ENTITLEMENT_MODE=enforce` | 商务权益与 checkout 以 Entitlement 为准 |
| Mock / 开发 | 订单所有者 `POST /api/v1/billing/orders/:id/simulate-paid`；管理台 `POST /api/v1/admin/orders/:id/simulate-paid`（仅 `local_billing`） |
| Sandbox 微信/支付宝 | 用户端 `/membership`：`providerHint` `wechat`→`wechat_pay_v3`、`alipay`→`alipay_f2f`；轮询 status + `complete`；密钥只在 Entitlement |
| Lite Entitlement webhook | `POST /api/v1/commerce/webhooks/entitlement`；`x-lw-timestamp` / `x-lw-nonce` / `x-lw-signature: v1=<base64url>` / `x-lw-event-id`；HMAC `${timestamp}.${nonce}.${rawBody}`；同步 **User.plan**（非生产微信/支付宝 PSP） |

生产核对（entitlement **API** 标志、错误签名 401、commerce 禁 simulate-paid、env **名称**）见 [生产支付就绪](/user/payment-production)。真实商户进件是 owner-ops，不随仓交付。

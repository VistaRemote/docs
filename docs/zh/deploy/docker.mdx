# Docker 部署

分层 Compose 栈位于 **`deploy`** 子仓（MetaRepo 内路径：`deploy/`）。规格见 Meta-Repo `spec/deploy-spec.md`（FR-STD-01 … FR-STD-07）。

## Compose 分层

| 文件 | 作用 |
| :--- | :--- |
| `compose/docker-compose.core.yml` | **server + PostgreSQL + Redis**（必需基线） |
| `compose/docker-compose.dev.yml` | 本地宿主机端口；可选 profile |
| `compose/docker-compose.prod.yml` | Caddy TLS；**不**暴露 DB/Redis 到宿主机 |
| `compose/docker-compose.external-db.yml` | 使用托管 Postgres/Redis，替代内置容器 |
| `compose/docker-compose.control-plane.yml` | 注入 Entitlement `:3040` + OIDC（不含 IdP 容器） |

根目录 `docker-compose.yml` 仅为 **core + dev** 的 `include` 快捷方式；运维文档仍推荐显式 `-f`。

## 本地（core + dev）

```bash
cd deploy
cp compose/.env.example .env    # 或 --env-file compose/.env.example

docker compose -f compose/docker-compose.core.yml -f compose/docker-compose.dev.yml up -d
```

| 服务 | 宿主机端口 | 说明 |
| :--- | :--- | :--- |
| **postgres** | **5637** | PostgreSQL 16（**唯一**关系型 OLTP；与 LuminaryWorks 一致） |
| **redis** | **6380** | 会话、BullMQ |
| **server** | **3000** | NestJS API + 信令 |

可选能力通过 dev 层 **profile** 按需启用（默认不启动 lab / 演示发布器）：

| Profile | 服务 | 宿主机端口 |
| :--- | :--- | :--- |
| `turn` | coturn | `3478`/`5349`，中继 `49160–49200/udp` |
| `ai` | Ollama、Qdrant、python-worker | **11435**、**6335**、`4100` — 见 [本地 AI 开发](/deploy/ai-local-dev) |
| `recording` | MinIO | API **19000**，控制台 **19001** |
| `admin` | 静态管理台（Caddy） | **8081** |
| `edge` | Caddy 80/443 | 本地 TLS 边缘 |

```bash
# 示例
docker compose -f compose/docker-compose.core.yml -f compose/docker-compose.dev.yml --profile turn up -d
docker compose -f compose/docker-compose.core.yml -f compose/docker-compose.dev.yml --profile recording up -d
```

在 MetaRepo 根目录（等价路径）：

```bash
docker compose -f deploy/compose/docker-compose.core.yml -f deploy/compose/docker-compose.dev.yml up -d
```

更多细节见 `deploy/README.md`（deploy-stack 子仓或 MetaRepo 内 `deploy/README.md`）。

## 录制（MinIO）

桌面 Phase 1 录制通过 dev 层 **`recording`** profile 启动 MinIO。默认 **生产** 栈**不含** MinIO — 在 `.env.prod` 配置外部 S3（`OBJECT_STORAGE_ENDPOINT`）。

```bash
docker compose -f compose/docker-compose.core.yml -f compose/docker-compose.dev.yml --profile recording up -d
```

| 调用方 | 端点 | 说明 |
| :--- | :--- | :--- |
| **server**（compose 内） | `http://minio:9000` | 容器网络 DNS |
| **Desktop Agent**（宿主机） | `http://127.0.0.1:19000` | 预签名 URL 须宿主机可达 |
| **MinIO 控制台** | http://127.0.0.1:19001 | 按需创建 bucket |

Bucket：**`vistaremote-recordings`**。Desktop 侧 `OBJECT_STORAGE_*` 与 `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` 一致，并设 `OBJECT_STORAGE_FORCE_PATH_STYLE=true`。

**不启 profile** — 单测或本地无 MinIO：`OBJECT_STORAGE_DRIVER=memory`（无需 compose profile）。

**分片大小** — Desktop 将非末片合并至 **≥5 MiB** 再 multipart PUT（否则 S3/MinIO 返回 `EntityTooSmall`）；末片可更小。`memory` 驱动经 `/parts` 仍接受小分片。运维提示见 [管理控制台](/user/admin-console) · [常见问题](/user/faq)。

## 生产

以 **core + prod** 为准（非 SFU 基线；仅在本机运行 VistaRemote coturn 时加 `--profile turn`）。

```bash
cd deploy
cp compose/.env.prod.example compose/.env.prod
# 填写 DOMAIN、密钥、TURN_EXTERNAL_IP
pnpm assert:prod-env

docker compose --env-file compose/.env.prod \
  -f compose/docker-compose.core.yml -f compose/docker-compose.prod.yml up -d --build
```

生产环境 **勿** 将 Postgres / Redis 映射到宿主机；默认 **不** 含 MinIO `recording` profile，录制走外部 S3。DNS、防火墙、健康检查、备份与回滚完整清单 → MetaRepo **`plan/v1-golive-checklist.md`**。

### `pnpm assert:prod-env`

在填写 `compose/.env.prod` 后、启动 compose 前运行（`deploy/` 目录）。脚本**只读校验**，失败时 `exit 1`，不修改任何文件。

| 目标 | 校验内容 |
| :--- | :--- |
| `compose/.env.prod.example`（**始终**） | 文件存在；含所需键：`DOMAIN`、`DB_PASSWORD`、三条 `VISTAREMOTE_*_JWT_SECRET`、`VISTAREMOTE_ADMIN_PASSWORD`、`TURN_USERNAME_PREFIX=vr:`、`TURN_REALM`、`ENTITLEMENT_MODE` / `ENTITLEMENT_BASE_URL` / `ENTITLEMENT_SERVICE_API_KEY` / `ENTITLEMENT_WEBHOOK_SECRET`、`INTERVENTION_HMAC_KEYS` / `INTERVENTION_MAX_SKEW_SEC` / `INTERVENTION_LINK_TTL_SEC`；`ENTITLEMENT_BASE_URL` 须含 **`:3040`**（禁止已退役 `7090`） |
| `compose/.env.prod`（**若已创建**） | 拒绝弱占位：`CHANGE_ME`、`vistaremote`、`miniosecret`、`password`/`admin`/`123456`、`dev-*` JWT、`host.docker.internal`；须设 `TURN_USERNAME_PREFIX=vr:`；Entitlement 非 `off` 时 `ENTITLEMENT_BASE_URL` 应指向 **`:3040`**；`ENTITLEMENT_MODE=enforce` 时 **`ENTITLEMENT_WEBHOOK_SECRET` 不得为空**（空则入站 webhook 恒 401） |
| `compose/.env.prod`（**若不存在**） | 仅校验 example，并输出 `WARN … example checked only` |

example 中的 `CHANGE_ME_*` 仅供复制模板；真实 `compose/.env.prod` 须替换为强密钥。本断言**不**表示生产支付 PSP 已交付——支付沙箱与凭证配置见 Go-Live 清单与 `deploy/README.md`。

## 共用 TURN

若 VistaCast 已占用 `3478`/`5349`，**不要**启用 `--profile turn`。在 server 环境变量中配置现有实例：`TURN_URL`、`TURN_REALM=turn.vistaremote.<domain>`、`TURN_USERNAME_PREFIX=vr:`。

## 私有化 LLM

Enterprise 可将 `AI_BASE_URL` 指向内网 **Ollama**（dev 层 `--profile ai`，宿主机 **11435**），无需公网 LLM。参见 [产品定位](/architecture/positioning) 与 [本地 AI 开发](/deploy/ai-local-dev)。

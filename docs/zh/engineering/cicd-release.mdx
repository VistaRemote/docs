# CI/CD 与版本发布

VistaRemote 采用 **分仓构建、分仓发布**：每个子仓库独立 SemVer tag、独立 GitHub Actions 流水线。契约包 `@vistaremote/shared` 发布后，会自动通知下游仓库升级依赖。

> 规范全文（含 FR 编号）：Meta-Repo [spec/cicd-release-spec.md](https://github.com/VistaRemote/vista-remote/blob/main/spec/cicd-release-spec.md)

## 版本与 Tag 约定

| 仓库 | Tag 格式 | 示例 | 产物 |
| :--- | :--- | :--- | :--- |
| **shared** | `vMAJOR.MINOR.PATCH` | `v0.2.0` | npm `@vistaremote/shared`（GitHub Packages） |
| **server** | `server-v*` | `server-v0.2.0` | Docker `ghcr.io/vistaremote/server` |
| **ai** | `ai-v*` | `ai-v0.2.0` | Docker `ghcr.io/vistaremote/ai` |
| **web** | `web-v*` | `web-v0.2.0` | 静态资源 artifact（client + admin） |
| **desktop** | `desktop-v*` | `desktop-v0.2.0` | 构建 artifact（安装包 P1） |
| **docs** | `docs-v*` | `docs-v0.2.0` | GitHub Pages |
| **deploy** | `deploy-v*` | `deploy-v0.2.0` | Compose 校验 / 发布说明 |
| **mobile** | `mobile-v*` | `mobile-v0.2.0` | 构建校验（商店 P1） |

各仓 `package.json#version` 可与 tag 对齐，但 **以 tag 为发版真相来源**。

## 发布流程（推荐顺序）

```text
1. shared 合并到 main
2. 打 tag v0.2.0 → release.yml 发布 npm 包
3. repository_dispatch → 各消费者 sync-shared.yml 自动开 PR
4. 合并 bump PR 后，各业务仓打 server-v0.2.0 / web-v0.2.0 …
5. deploy 更新 compose 镜像 tag → deploy-v0.2.0
```

### 1. 发布 shared

```bash
cd shared
# 确保 package.json version 与 tag 一致
git tag v0.2.0
git push origin v0.2.0
```

工作流 `shared/.github/workflows/release.yml` 会：lint → test → build → `pnpm publish` → 通知 `server` / `web` / `ai` / `desktop` / `mobile`。

### 2. 消费者自动 bump

各仓 `sync-shared.yml` 收到 `shared-published` 后：

- 将 `@vistaremote/shared` 升级为 `^0.2.0`
- 运行 `pnpm install`、lint、test、build
- 自动创建 PR：`chore(deps): bump @vistaremote/shared to 0.2.0`

维护者 Review 并合并。

### 3. 发布业务服务

```bash
cd server
git tag server-v0.2.0
git push origin server-v0.2.0
```

## 本地开发 vs CI vs 生产

| 环境 | `@vistaremote/shared` 来源 |
| :--- | :--- |
| **Meta-Repo 联调** | `file:../shared`（默认，见各仓 `package.json`） |
| **各仓 GitHub Actions** | composite action `setup-shared` 检出兄弟目录 |
| **Docker / 离线构建** | GitHub Packages 固定 SemVer |

恢复本地 `file:` 依赖（发版 bump 后）：

```bash
# Meta-Repo 根目录
node tooling/scripts/restore-shared-file-deps.mjs
```

手动 pin 版本（不发 dispatch 时）：

```bash
node tooling/scripts/pin-shared-version.mjs 0.2.0 server web
```

## CI 流水线一览

| 工作流 | 触发 | 作用 |
| :--- | :--- | :--- |
| `ci.yml` | push / PR | setup-shared → lint → test → build |
| `sync-shared.yml` | `shared-published` | 自动 bump 依赖并开 PR |
| `release.yml` | tag | 发布镜像 / 静态站 / npm |
| `dependency-review.yml` | PR | 依赖变更审查 |
| CodeQL | push / PR | 静态安全分析 |

**server** 另有 `perf.yml`（k6）；**web** 另有 `e2e.yml`（Playwright）。

Meta-Repo 根目录 `meta-ci.yml` **仅**检查脚手架（tooling、`.github`），不替代子仓 CI。

## 一次性配置（维护者）

在 **`VistaRemote/shared`** 仓库 Settings → Secrets：

| Secret | 用途 |
| :--- | :--- |
| `VISTAREMOTE_CI_PAT` | 跨仓 `repository_dispatch`（需 `repo` + `workflow`） |

可选 Variable：`ENABLE_SHARED_DISPATCH=false` 临时关闭自动通知。

消费者从 GitHub Packages 安装时，复制 `.npmrc.example` 为 `.npmrc`（或使用 CI 内生成的配置）。

## 同步 workflow 模板

在 Meta-Repo 根目录更新子仓 Actions：

```bash
node tooling/scripts/setup-github-workflows.mjs
```

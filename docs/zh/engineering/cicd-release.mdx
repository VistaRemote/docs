# 发布流程

VistaRemote 采用 **分仓构建、分仓发布**：每个子仓库独立 SemVer tag、独立 GitHub Actions 流水线。契约包 `@vistaremote/shared` 发布后，会自动通知下游仓库升级依赖。

> 规范全文（含 FR 编号）：Meta-Repo [spec/cicd-release-spec.md](https://github.com/VistaRemote/vista-remote/blob/main/spec/cicd-release-spec.md)

## Tag 约定

每个仓库用自己的前缀加上语义化版本。发版以 **tag** 为准，`package.json` 里的版本与这次 tag 保持一致。

| 仓库 | Tag 前缀 | 产物 |
| :--- | :--- | :--- |
| **shared** | `v` | npm `@vistaremote/shared`（GitHub Packages） |
| **server** | `server-v` | Docker `ghcr.io/vistaremote/server` |
| **ai** | `ai-v` | Docker `ghcr.io/vistaremote/ai` |
| **web** | `web-v` | 静态资源（client + admin） |
| **desktop** | `desktop-v` | Windows / macOS 安装包 |
| **docs** | `docs-v` | GitHub Pages |
| **deploy** | `deploy-v` | Compose 校验 / 发布说明 |
| **mobile** | `mobile-v` | Android 安装包 |
| **downloads**（公开） | `v` | Windows Agent + Android APK（用户可匿名下载） |

各仓 `package.json#version` 可与 tag 对齐，但 **以 tag 为发版真相来源**。

## 用户侧安装包（公开仓）

源码仓（`desktop` / `mobile`）可保持 **私有**。面向用户的安装包统一发布到公开仓库 **[VistaRemote/downloads](https://github.com/VistaRemote/downloads)**，官网 `/download` 默认指向该仓的 `releases/latest/download`。

Meta-Repo 一键：

```bash
pnpm pack:publish          # pack:all + 上传到 VistaRemote/downloads Release
pnpm publish:downloads     # 仅上传已有产物（跳过打包）
```

要求：本机已 `gh auth login`，且 `desktop` / `mobile` 的 `package.json` version 一致。Windows Agent 建议在 Windows 或 `desktop` 仓 Actions（`windows-latest`）产出后再上传；Android APK 可在 macOS 本地 `pnpm pack:mobile`。

官网默认：

- `NEXT_PUBLIC_RELEASE_BASE=https://github.com/VistaRemote/downloads/releases/latest/download`
- `NEXT_PUBLIC_RELEASE_VERSION` 与安装包文件名中的发布标识一致

## 发布流程（推荐顺序）

1. 把 `shared` 合并到 `main`。
2. 在 `shared` 按前缀 `v` 打 tag 并推送。`release.yml` 发布 npm 包。
3. `repository_dispatch` 让各消费者的 `sync-shared.yml` 自动开依赖升级 PR。
4. 合并这些 PR 后，再给 `server`、`web` 等仓库按各自前缀打 tag。
5. `deploy` 把 Compose 里的镜像指到刚发布的 tag，再给 `deploy` 打 tag。

### 1. 发布 shared

在 `shared` 仓库确认 `package.json` 与即将推送的 tag 一致，然后把 tag 推到 `origin`。

工作流 `shared/.github/workflows/release.yml` 会：lint → test → build → `pnpm publish` → 通知 `server` / `web` / `ai` / `desktop` / `mobile`。

### 2. 消费者自动升级依赖

各仓 `sync-shared.yml` 收到 `shared-published` 后：

- 把 `@vistaremote/shared` 升到刚发布的版本
- 运行 `pnpm install`、lint、test、build
- 自动创建依赖升级 PR

维护者 Review 并合并。

### 3. 发布业务服务

在对应仓库（例如 `server`）按该仓前缀打 tag 并推送到 `origin`，由该仓的 `release.yml` 发布镜像或静态资源。

## 本地开发 vs CI vs 生产

| 环境 | `@vistaremote/shared` 来源 |
| :--- | :--- |
| **Meta-Repo 联调** | `file:../shared`（默认，见各仓 `package.json`） |
| **各仓 GitHub Actions** | composite action `setup-shared` 检出兄弟目录 |
| **Docker / 离线构建** | GitHub Packages 固定 SemVer |

恢复本地 `file:` 依赖（发版 bump 后）：

```bash
# Meta-Repo 根目录
node tooling/scripts/restore-shared-file-deps.mjs
```

不走自动通知、只在指定仓库固定 `@vistaremote/shared` 时，在 Meta-Repo 根目录执行 `pin-shared-version.mjs`：第一个参数是要固定的语义化版本，后面是仓库名（如 `server`、`web`）。

## CI 流水线一览

| 工作流 | 触发 | 作用 |
| :--- | :--- | :--- |
| `ci.yml` | push / PR | setup-shared → lint → test → build |
| `sync-shared.yml` | `shared-published` | 自动 bump 依赖并开 PR |
| `release.yml` | tag | 发布镜像 / 静态站 / npm |
| `dependency-review.yml` | PR | 依赖变更审查 |
| CodeQL | push / PR | 静态安全分析 |

**server** 另有 `perf.yml`（k6）；**web** 另有 `e2e.yml`（Playwright）。

Meta-Repo 根目录 `meta-ci.yml` **仅**检查脚手架（tooling、`.github`），不替代子仓 CI。

## 一次性配置（维护者）

在 **`VistaRemote/shared`** 仓库 Settings → Secrets：

| Secret | 用途 |
| :--- | :--- |
| `VISTAREMOTE_CI_PAT` | 跨仓 `repository_dispatch`（需 `repo` + `workflow`） |

可选 Variable：`ENABLE_SHARED_DISPATCH=false` 临时关闭自动通知。

消费者从 GitHub Packages 安装时，复制 `.npmrc.example` 为 `.npmrc`（或使用 CI 内生成的配置）。

## 同步 workflow 模板

在 Meta-Repo 根目录更新子仓 Actions：

```bash
node tooling/scripts/setup-github-workflows.mjs
```

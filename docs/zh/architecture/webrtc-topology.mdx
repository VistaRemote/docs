# WebRTC 拓扑与媒体路径

VistaRemote **默认 1:1 使用 P2P + STUN/TURN（coturn）**；在需要 **多用户观看同一桌面**、**P2P 穿透反复失败** 或 **TURN 中继压力过大** 时，切换为 **mediasoup SFU** 推流。

> **商业化**：SFU 在 **14 天试用期内** 可免费体验；试用结束后须订阅 **Pro** 及以上。详见 [试用期与付费能力](./commercial-trial)。

> 规范：Meta-Repo `spec/webrtc-architecture-spec.md`

## 为什么不默认 SRS？

| 考量 | 说明 |
| :--- | :--- |
| 业务形态 | 远程桌面 + 企业监控，**非**万级观众直播 |
| 并发 | 数十路会话级并发即可，mediasoup + Node 侧车足够 |
| 生态 | 全栈 TypeScript，与 server/ai 同运维模型 |
| 成本 | SRS 独立 C++ 媒体栈，开发与运维面更大 |

## 模式对照

| 场景 | 模式 | 媒体怎么走 |
| :--- | :--- | :--- |
| 1 主控 : 1 被控 | **P2P** | 端到端；必要时经 coturn **relay** |
| 1 被控 : N 主控 | **SFU** | 被控 → mediasoup **一路**上行；N 路下行 |
| P2P 失败 ≥2 次 | **SFU** | Server 策略回退 |
| coturn 负载过高 | **SFU** | 新会话优先 SFU，减轻 TURN 压力 |

```text
         ┌─────────────┐
主控 Web ─┤   NestJS    ├──► 信令 / 鉴权 / 模式决策
         └──────┬──────┘
                │
     P2P ◄──────┼──────► coturn (STUN/TURN)
                │
         SFU ◄──┴──► mediasoup-worker
                ▲
被控 Agent ─────┘
```

## 通道分工

| 通道 | 用途 |
| :--- | :--- |
| RTP (DTLS-SRTP) | 屏幕视频 |
| DataChannel `control` | 键鼠 / 触控 |
| DataChannel `telemetry` | Enterprise 遥测 |
| WebSocket | SDP / ICE / `session-mode` |

## 重要约束

- **NestJS 不转发 RTP**，只做信令与调度。
- ICE/TURN 凭证 **仅** 从 Server API 获取。
- 被控在 SFU 模式下 **只推一路**，避免 CPU 随观众数线性增长。

# 架构总览

VistaRemote 采用 **扁平 Meta-Repo**：`shared`、`server`、`ai`、`web`、`desktop`、`mobile`、`docs`、`deploy` 各自独立 Git 仓库，契约优先、按仓发布。

## 背景与定位

企业远程桌面是运维与协助的基础设施。传统方案常见问题：

- **高延迟 / 私有协议**：跨防火墙或跨国链路体验差
- **单体 C/C++ 栈**：现代 Web/移动全栈迭代成本高
- **中心化云中继**：敏感画面与控制面有外泄风险

VistaRemote 以 **WebRTC（P2P / SFU 混合）** 做实时远控，并可选 **私有化 AI**：会话摘要、以及 Viewer 里对标 **Windows-MCP / MacOS-MCP** 的「看屏 → 点击/输入」协助（默认关闭、二次同意）。

| 支柱 | 说明 |
| :--- | :--- |
| **WebRTC 原生** | 实时控制与串流，不是只录不控 |
| **开源可私有化** | PostgreSQL、对象存储、可选 Ollama；数据留在机房 |
| **TypeScript 全栈** | 招聘与二开成本更低，Spec-Driven |
| **AI 按设计隔离** | LLM 只在 `ai` Worker；不内嵌到 server/desktop |

更细的定位见 [产品定位](/architecture/positioning)；AI 协助用法见 [AI 协助](/user/ai-copilot)。

## 技术栈要点

- **实时**：WebRTC 远程桌面（1:1 P2P，1:N SFU）
- **服务端**：NestJS + Fastify + TypeORM + PostgreSQL 16+
- **前端**：React / Rsbuild；Desktop 为 Electron；Mobile 为 React Native
- **AI**：独立 `ai` 仓库 + BullMQ；可选 computer-use 协助
- **性能热路径**：截屏/编码可用 Rust（napi-rs），不污染主工程 TypeScript

## 为何不用单一 Monorepo

Electron 原生插件与 React Native Metro 对提升 `node_modules` 冲突明显。分仓能保证各端构建可靠；跨仓契约统一放在 `@vistaremote/shared`。

      #生产支付就绪（运维）

      面向部署方核对 mock → sandbox → production。LuminaryWorks Entitlement 已实现支付 adapter；这不等于 live 商户已启用。Lite 收银（commerce complete / status、Entitlement 入站 webhook）可以把本地 User.plan 写到缓存；微信 / 支付宝商户进件、notify DNS 与生产 PSP 密钥是 owner-ops，不随 VistaRemote 交付。产品侧 outbox 履约投递可能仍在推进。不要把商户密钥写入 git。

      架构说明见 商业化与计费；管理台模块见 管理控制台。Spec：spec/billing-commerce-spec.md。

      #会员购买 vs 钱包

      VistaRemote 没有预付费钱包、余额或「充值」SKU。用户购买的是 Pro / Ultra 订阅 offerings（Client /membership → commerce BFF → Entitlement）。

      沙箱打通要点：

      1. 统一 OIDC 登录一次，写入 users.logtoSub（commerce X-Act-As-Subject 用 Logto sub，不是本地 User UUID）
      2. Entitlement 非生产且配置了 PAYMENT_CONFIG_MASTER_KEY 时，可自动种子 mock 支付配置；或在 Admin 启用 mock/alipay sandbox
      3. Membership 选套餐 → 支付方式（优先 mock）→ 完成支付；mock 会在 complete 时履约并同步本地 User.plan
      4. 生产微信/支付宝商户进件仍在 Entitlement owner-ops；本产品不提供跨产品钱包

      #路径：mock → sandbox → production

      阶段典型配置行为
      Mock（本地）ENTITLEMENT_MODE=off本地订单 + 套餐。订单所有者可用 POST /api/v1/billing/orders/:id/simulate-paid（Controller JWT）。管理台 订单「模拟支付」只打 POST /api/v1/admin/orders/:id/simulate-paid，且仅 source=local_billing。
      SandboxENTITLEMENT_MODE=enforce，中央 Entitlement 可达Web 用户端 /membership：catalog providerHint wechat → wechat_pay_v3，alipay → alipay_f2f；可出 QR / codeUrl / 跳转。支付后页内 轮询 GET .../orders/:id（约 2s，约 2 min 上限），回跳或点「完成支付」会 POST .../complete，再刷新本地权益。Sandbox 密钥只放在 Entitlement，不进本仓。不是 生产微信/支付宝商户 notify。
      Production同上模式 + 生产 Entitlement / PSP（owner-ops）VistaRemote lite webhook POST /api/v1/commerce/webhooks/entitlement 可同步 User.plan。微信 / 支付宝平台 notify 入站在 LuminaryWorks Entitlement，不在 VistaRemote。真实商户进件、证书与平台回调 未随本仓交付。

      Lite 入站 order.fulfilled（POST /api/v1/commerce/webhooks/entitlement）使用 HMAC 头（FR-BILL-06），不是微信 / 支付宝平台 notify 验签：

      头要求
      content-typeapplication/json
      x-lw-timestampUnix 秒（±300s 时窗）
      x-lw-nonce≥8 字符；防重放
      x-lw-signaturev1=<base64url>
      x-lw-event-id幂等事件 ID

      签名：HMAC-SHA256(ENTITLEMENT_WEBHOOK_SECRET, timestamp.nonce.rawBody) → base64url；须对 未改动的原始 body 验签（勿重序列化 JSON）。ENTITLEMENT_WEBHOOK_SECRET 为本 ingress 的 HMAC secret，值须等于 Entitlement ENTITLEMENT_ORDER_FULFILLED_TARGETS.vistaremote.secret。旧头 X-Entitlement-Signature 常量相等 硬切 401，无 fallback。密钥未配置时同样 401（诚实拒绝，非静默 mock）。

      履约失败（本地套餐投影写失败）会进入 commerce_webhook_fulfillments 重试队列；达上限 → 死信。Admin：GET/POST /api/v1/admin/commerce-webhook/*（status / dead-letters / process-once / replay|ignore）；审计 commerce.webhook.*（FR-BILL-07）。

      Runbook：微信 / 支付宝 商户进件仍 owner-ops，不随本仓交付。

      #Webhook 用户映射（Logto sub）

      验签通过后，order.fulfilled 载荷里的 subjectId 必须是 Logto OIDC sub，服务端用 users.logtoSub 查找本地用户（不是本地 User UUID，也不会自动建用户）。

      用户来源logtoSub能否靠 webhook 写 User.plan
      Web / OIDC 登录后 POST /api/v1/auth/oidc/exchange已写入✓
      管理台本地注册 / 仅 Controller JWT常为 null✗ → 400 WEBHOOK_USER_NOT_FOUND

      本地-only 用户（无 Logto 绑定）开通套餐请用：

      • 管理台 用户 → 改套餐（Admin plan grant），或
      • 订单所有者走 commerce POST .../complete / GET .../orders/:id（CommercePlanSyncService.syncForAccessToken，用 Bearer token 解析本地用户）

      试运营路径见 Meta-Repo plan/trial-ops-checklist.md。

      #VistaRemote server 环境变量（仅名称）

      下列名称来自 server 源码与 server/.env.example。不要编造取值；生产密钥放密钥库 / Entitlement 主机，不要提交。

      本仓 没有 COMMERCE_* 环境变量。Commerce BFF 使用 ENTITLEMENT_BASE_URL 转发 /v1/...。

      名称用途
      ENTITLEMENT_MODEoff | shadow | enforce | offline_license
      ENTITLEMENT_BASE_URL中央 Entitlement 基址
      ENTITLEMENT_SERVICE_API_KEYM2M X-Service-Key
      ENTITLEMENT_WEBHOOK_SECRETLite 入站 HMAC secret（= Entitlement TARGETS.vistaremote.secret）；空则 webhook 一律 401
      COMMERCE_WEBHOOK_POLL_MS履约重试轮询间隔（默认 15000；<=0 关闭）
      COMMERCE_WEBHOOK_MAX_ATTEMPTS履约重试上限（默认 5 → 死信）
      ENTITLEMENT_CACHE_TTL_MS权益缓存 TTL
      ENTITLEMENT_OFFLINE_GRACE_MS离线宽限
      ENTITLEMENT_DEPLOYMENT_ID部署标识
      ENTITLEMENT_LICENSE_PUBLIC_KEYS离线 License 公钥 JSON（offline_license）
      ENTITLEMENT_LICENSE_PAYLOAD离线 License 载荷（offline_license）
      ENTITLEMENT_LICENSE_ALLOW_GRACE离线 License 宽限开关
      PRODUCT_CODE产品码（示例为 vistaremote）
      BILLING_ALLOW_SIMULATE_PAID仅当 NODE_ENV=production 时：设为 true 才允许 simulate-paid。生产应 省略或非 true
      NODE_ENVproduction 时默认禁用 simulate-paid

      微信 / 支付宝 商户号、APIv3 密钥、证书、支付宝应用密钥 属于 Entitlement / PSP，不是 VistaRemote server 变量。ENTITLEMENT_TRIAL_PURGE_* 是试用录制清理，与支付回调无关。

      #用户端 Membership（sandbox，非 PSP live）

      Web 用户端 /membership（当前 viewer Admin 没有 /membership 路由）：

      1. 接受条款 → 选 Pro/Ultra SKU → 选 微信支付 或 支付宝（catalog providerHint，不是 Entitlement adapter id）。
      2. 去支付 → POST /api/v1/commerce/orders 再 .../pay。可能出现二维码、支付链接或跳转。
      3. 页内提示「正在等待支付确认…」并轮询订单 status；也可点 完成支付（complete）。
      4. status 为 paid / fulfilled / completed / success 后刷新权益。页上沙箱说明 不是 生产商户 notify。

      封闭试用也可走管理台 用户 改套餐，不必走收银。

      #核对清单

      • 系统页权益标志（FR-WAD-52）：管理台 系统 → 权益/支付配置。GET /api/v1/admin/system/entitlement 只返回 entitlementMode、entitlementBaseUrlConfigured、webhookSecretConfigured。禁止出现 ENTITLEMENT_WEBHOOK_SECRET 或 Base URL 明文。可 复制权益状态 JSON 核对。
      • 错误签名拒绝：对 POST /api/v1/commerce/webhooks/entitlement 发送错误或缺失的 x-lw-signature（或仅旧 X-Entitlement-Signature）→ 401；本地 User.plan 不变。密钥未配置时同样 401。
      • 履约死信可查（FR-BILL-07）：Admin GET /api/v1/admin/commerce-webhook/dead-letters 可见失败事件；可 process-once / replay / ignore。微信/支付宝商户进件仍 owner-ops。
      • commerce 禁止 simulate-paid：管理台「模拟支付」仅 local_billing pending 行可见。POST /api/v1/admin/orders/:id/simulate-paid 对 source=commerce 返回 400 COMMERCE_SIMULATE_PAID_FORBIDDEN（UI 提示走 Membership complete / webhook）。不要用 Admin JWT 打 POST /api/v1/billing/orders/:id/simulate-paid。
      • 生产关闭模拟支付：NODE_ENV=production 且未设 BILLING_ALLOW_SIMULATE_PAID=true 时，simulate-paid 返回 400 SIMULATE_PAID_DISABLED（UI：「生产环境已禁用模拟支付」）。
      • Webhook 用户映射：subjectId 须为 Entitlement 侧 Logto sub，且本地 users.logtoSub 已绑定；否则 400 WEBHOOK_USER_NOT_FOUND。Admin 本地注册用户请用改套餐或 Client Membership complete/status，不要指望 webhook 自动开通。
      • 开通路径：sandbox 走 Client Membership pay + complete / status 轮询（或 lite webhook paid/fulfilled，且用户已 OIDC 绑定）后，管理台 用户 列表出现对应 plan。这是本地缓存，不是生产 PSP 对账完成的证明。
      • 密钥不进 git：.env、CI 日志、Admin JSON 均无商户密钥。

      #未随仓交付（owner-ops）

      以下由部署方在 LuminaryWorks Entitlement / 支付平台控制台 完成。VistaRemote 不接收微信 / 支付宝平台 notify；本仓只有 lite POST /api/v1/commerce/webhooks/entitlement。不附带生产商户包：

      • 微信商户进件、APIv3 密钥与平台证书、指向 Entitlement 的支付回调 URL
      • 支付宝应用与密钥、当面付 / 沙箱切生产
      • PayPal / Wise 等其它渠道的生产凭据
      • 把上述密钥写入 Entitlement 环境（不要写入 server/.env 并提交）

      完成进件后，仍用本页清单核对 entitlement API 标志、错误签名 401、以及 commerce 不可 simulate-paid。

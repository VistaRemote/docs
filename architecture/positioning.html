      #VistaRemote 产品定位与核心优势

      MetadataValue
      文档产品定位（对内对外统一口径）
      版本1.2.0
      更新2026-09-20

      #1. 一句话定位

      VistaRemote 是面向企业与开发者的 开源、可私有化部署 的 远程桌面 + 边缘设备舰队管理 平台：以 WebRTC 实现低延迟实时画面与控制；以 Device Fleet 管一批边缘 / 办公设备 — 包括 群控键鼠、批量命令、多屏监控墙、虚拟显示器、审计与 RBAC；企业私有化还可开通 带外管理（如 Intel AMT）。数据留在企业自有基础设施内。

      与 VistaCast：Cast 看业务视频，Remote 管 Edge Box；可组合「摄像头 + Edge AI Box + VistaRemote 管理」B2B 方案。

      企业能力口径：群控、监控墙、虚拟屏、带外等均属 产品能力范围，对外方案可写「具备」。购买 Enterprise 或签订合同后开通权益；更大监控墙槽位、现场定制与带外集成按合同交付与验收。监控墙默认以 缩略图观察 + 点选高质量控制 省带宽，超大型高清同屏按加购验收，不作为免费默认标配。详见 设备舰队与企业能力。

      #2. 与传统监控方案对比

      维度传统桌面监控 / 录屏软件VistaRemote
      传输技术多为专有 TCP 协议或厂商中继，延迟与防火墙适配参差标准 WebRTC：P2P + TURN 低延迟 1:1；多观众或 TURN 压力大时自动 mediasoup SFU（非 SRS 直播栈）
      观看体验录屏回放为主，实时卡顿常见WebCodecs 硬解 + 抖动缓冲，减轻浏览器主线程卡顿
      实时性偏「事后回放」，实时远程体验弱实时远程控制 + 可选录制，同一套链路
      AI 能力多绑定厂商云端，模型与数据不可控独立 ai 服务，支持公有 LLM API 或 Ollama 私有化
      部署闭源安装包 + 厂商云开源 + Docker Compose 自建（信令、PostgreSQL、存储、AI 均可内网）
      扩展C++/Delphi 老栈，二开困难全栈 TypeScript，契约在 shared，Spec 驱动

      #3. 与企业级商业监控软件对比

      维度典型企业级桌面监控（商业）VistaRemote
      授权闭源、席位昂贵个人非盈利免费；商业使用须签约（见 开源协议）
      数据主权录像与分析数据常经厂商云企业自建：PostgreSQL + MinIO + 内网 AI，满足合规与等保倾向
      AI 与隐私黑盒分析，难以审计 Prompt 与出境策略、录制、LLM 端点 可配置，审计日志可追踪
      远程协助监控为主，远程控场为辅或另购监控 + 远程控制 统一 WebRTC 架构
      人才厂商生态绑定NestJS / React / RN / Electron，国内开发者储备大

      企业版能力（关键词/窗口标题触发录制、多屏监控、外发与删文件告警、效率报告等）见 Meta-Repo spec/enterprise-security-spec.md。

      #4. 技术栈优势（开发与交付）

      #4.0 选型一句话

      不需要千万级并发时，VistaRemote 往往是性价比最高的选择 — 全栈 TS、Spec 驱动、Meta-Repo 快构建、私有化 AI，二开与交付速度显著优于传统 C++/闭源远控。

      #4.1 全面拥抱 TypeScript（与 Python 分工）

      • 一端语言：shared 契约贯通 server、web、desktop、mobile、ai。
      • TS 与 Python 都简单易学：主业务 TS；重 ML 仅在 ai/python-worker，降低团队认知负担。
      • 招人友好：国内前端/Node 工程师规模大，上手周期短。
      • 二开成本低：插件、定制 Admin、对接企业 SSO/IM 均以 TS 模块扩展为主 — 见 二开指南。
      • AI 协作：Spec-Driven + Vibe Code，结构化 Spec 作为 AI 实现输入。

      #4.2 不采用 Flutter；Rust 负责底层

      业界常宣传「Flutter + Skia/Impeller GPU 比 JS 跨端更流畅」。VistaRemote 的判断是：

      • UI 层：统一 React 19 + Rsbuild（Web/Desktop）与 React Native 新架构 + JSI（Mobile）。Rspack/Rsbuild 本身由 Rust 编写，已把构建冷启动打到极低；Electron 的 WebGL2/WebGPU、RN 的 JSI 已解决远控场景里过去的「桥接延迟」问题。
      • 底层：DXGI 截屏、NVENC 硬件编码、系统键鼠 Hook 必须由 Rust（N-API / Native Module）实现，Dart/Flutter 无法替代，引入 Flutter 只会多一套 Dart 维护面。

      详见 跨端技术栈（为何不用 Flutter）。

      #4.3 构建与部署简单

      层级选型对团队的意义
      前端Rsbuild（Rspack）编译快，与 Webpack 生态兼容
      后端NestJS + TypeORM国内 Node 企业级事实标准
      数据库PostgreSQL 16运维熟悉度高，云厂商托管成熟（见下文）
      部署deploy Compose 模板单机/内网一键拉起全栈

      #4.4 为何选用 PostgreSQL（LuminaryWorks 生态）

      这是 与 LuminaryWorks 生态对齐 的工程选择：

      考量说明
      生态一致identity、auth-core 与共享基础设施已统一 PostgreSQL
      跨项目复用TypeORM 实体、迁移与运维 playbook 可在生态内共享
      能力扩展JSONB、窗口函数；可选 pgvector 与 Qdrant 并存
      TypeORM 支持与 NestJS + pg 驱动组合成熟，server 已接入

      规范说明：全项目 Spec 与部署文档以 PostgreSQL 16+ 为唯一关系型 OLTP。见 Meta-Repo ADR-0008 与 spec/server-spec.md。

      #5. 安全可控：企业为什么敢用我们的 AI

      1. 私有化部署：Server、PostgreSQL、MinIO（录制）、Redis、ai Worker 均可部署在企业 VPC。
      2. LLM 可选内网：Enterprise 配置 AI_BASE_URL 指向 Ollama / 私有推理网关，会话摘要与报告 不出域。
      3. 职责分离：信令路径（server）与重计算（ai）分进程，便于防火墙分区。
      4. 透明审计：连接、录制播放、套餐变更、安全事件写入 PostgreSQL，Admin 可查询导出。
      5. 开源可审：核心链路可代码审计，避免「黑盒监控」信任危机。

      #6. 三大核心卖点（对外传播）

      1. WebRTC 实时远程 — P2P 优先的低延迟控制；多人观摩时 SFU 单路上行，不把压力全堆在 TURN；键鼠走 DataChannel，信令走 WebSocket。
      2. 开源 + 可自建 AI — 相比商业监控，数据与模型边界企业自控。
      3. TypeScript 全栈 + 现代架构分工 — React/RN 做产品、Rust 做底层、BullMQ 做 AI 任务；好招人、好二开、好部署。
        • 面向老板/运维/开发的完整叙事：技术选型优势。

      #7. 客户端性能（摘要）

      端策略
      Web 主控WebCodecs 硬解、Worker/OffscreenCanvas 解码、JitterBuffer — 避免 React 主线程卡顿
      MobileJSI + 原生视频视图（react-native-webrtc 新架构）
      Desktop Agent端侧采集与录制；硬件编码；减轻服务端媒体压力

      详情：Desktop 性能架构 · WebRTC 开发调优。

      #7.1 端侧现代 AI（相对老竞品）

      传统远控多为 C++/闭源，难以嵌入 PaddleOCR-slim + 边缘 Qwen2.5-VL + 规则引擎。VistaRemote 在 desktop/edge-ai 与 ai 仓库将 AI 作为 可演进管道，与监控、录制同一套 TS 生态。

      #8. Meta-Repo 与构建

      对比MonorepoVistaRemote
      冷启动全仓 install + 复杂图单仓 Rsbuild 数百毫秒
      原生冲突Electron C++ 与 RN 常冲突分仓独立 node_modules
      CI巨型流水线分仓 tag，全球分发轻量
      二开改一层牵动全局只拉 web+server 亦可

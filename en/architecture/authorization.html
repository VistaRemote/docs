      #Authentication and authorization

      VistaRemote uses a hybrid model—not pure RBAC and not pure ABAC:

      Authenticate (JWT) → Plan entitlements → RBAC (job role) → ABAC (resource) → allow/deny + audit

      Normative spec: spec/authorization-spec.md in the Meta-Repo.

      #RBAC or ABAC?

      ModelStandalone?Role here
      RBACNo (one layer)Stable job roles: platform super_admin / admin / viewer; org org_owner / it_support / member, etc.
      ABACNo (one layer)Resource scope: ownerId, orgId, allowOrgSupport, room membership
      PlanThird layerfree / pro / enterprise for commercial features (recording, AI, enterprise security)

      #Two “admin” concepts

      AccountAppTypical user
      Platform adminweb/apps/adminSaaS operators
      Org user (client)web/apps/client, mobileEmployees, executives, IT support

      IT support uses the client app with orgRole=it_support. Platform operators use admin JWT for global user/plan management.

      #Persona mapping

      Business labelTechnical setup
      EmployeeUser member
      Executive / ownerUser org_owner + Enterprise plan
      IT supportUser it_support + device allowOrgSupport
      Platform adminAdmin admin / super_admin
      Compliance read-onlyAdmin viewer or User security_auditor

      ChannelCredential

      Policy helpers live in shared/src/auth/; WSS/SSE handshake enforcement is P3 (FR-MSG-10/11).

      #Common tasks

      #Grant Pro to a user

      1. Closed trial preferred: Admin Users → change plan (writes local User.plan immediately).
      2. Sandbox checkout: the user opens Web Client /membership, picks providerHint (WeChat / Alipay), then waits for polling or clicks Complete payment. That is not live merchant notify.
      3. Local pending orders only: Admin Orders Simulate paid (POST /api/v1/admin/orders/:id/simulate-paid). The order owner may also call /api/v1/billing/orders/:id/simulate-paid with a Controller JWT. Commerce orders return COMMERCE_SIMULATE_PAID_FORBIDDEN.
      4. Entitlements apply after the user refreshes the client or signs in again.

      #Disable a user

      1. Users → select user → disable.
      2. The user cannot start new sessions. For an active session, open Sessions and force disconnect.

      #Monitor wall layout

      Product capability (Enterprise): multi-device thumbnail observe; click into high-quality remote control when needed. Larger slot counts can be purchased and accepted under enterprise contracts. See Device Fleet & Enterprise.

      Ops quick steps:

      1. Open /monitor-wall and bind active sessions to slots.
      2. Save layout (requires admin.write) to persist bindings.
      3. URL seeds such as s0–s3 can prefill slots.
      4. Click a live slot to open a control session (enterprise wall / remote entitlements required).

      (Version history and API notes below remain for implementers.)

      Layout persistence (1.35.0) — persists slot-to-session bindings.

      1. Open /monitor-wall. URL query s0–s3 (aliases slot0–slot3 accepted) with session IDs take priority and are not overwritten by a saved layout.
      2. With no URL seeds, the page GETs /admin/monitor-wall/layout to restore the last saved slot bindings.
      3. After changing slots, click Save layout to PUT the same path (requires admin.write; read-only admins see the button disabled). Saving the layout does not auto-start in-wall observe or SFU connections.
      4. Per-slot in-wall observe provides thumbnail observe; click a live slot for high-quality control when needed. Enterprise multi-screen wall scale: Device Fleet & Enterprise.
      5. 1.36.0 — POST /admin/rooms/:roomId/observe returns shared AdminObserveTicket (signalingTicket, role: observe, expiresAt, …). SFU observe parameters are issued by the server.
      6. 1.37.0 / 1.38.0 — Filter audit by action preset monitor-wall layout (admin.monitor_wall.layout). 1.38.0 — Save layout writes audit meta with roomIds (bound session ids) and the first roomId. Matching rows show Monitor wall in Related → /monitor-wall, or /monitor-wall?s0=<roomId> from meta / resource / target roomId / room_id. Slot 0 seed only; start observe from the wall when needed.
      7. 1.44.0 — Page tips cover layout save and in-wall / enterprise multi-screen observe.

      #Jobs, reports, and recordings (1.37.0)

      1. Jobs — List filters (id, name, state, failedReason) sync to the URL when you search (shareable links; overview failed jobs opens /jobs?state=failed).
      2. Recording summarize jobs — Rows with type recording.summarize and id summarize-{recordingId} show Recording in Actions, linking to /recordings?recordingId=… (other job types have no recording jump).
      3. Efficiency reports — Open recordings opens /recordings with the same active substring filters (userId, sessionId, deviceId, recordingId); empty filters open the full list.

      #Pairings list (1.39.0 / 1.40.0 / 1.41.0)

      FR-WAD-109 — read-only ops view of recent pairing codes; not a code generator or SFU / monitor-wall feature.

      1. Open /pairings under Operations (nav between Devices and Orders), from Overview → Pairings NavCard (1.41.0), from Devices → Actions → Pairings (?deviceId= pre-filled, 1.41.0), or from System → pairing-policy section Open pairings (1.40.0).
      2. The page calls GET /api/v1/admin/pairings (requires admin.read). Default returns up to 100 recent rows; optional query limit is clamped 1–500.
      3. Server filters: deviceId and numericCode (substring, case-insensitive); userId filters by the device owner resolved from the devices table; consumed (1.41.0) — yes = consumedAt set (code already used), no = consumedAt null (unused); unknown values are ignored.
      4. Search fields sync to ?deviceId=, ?userId=, ?numericCode=, and ?consumed=yes|no in the URL (shareable links). The Consumed select offers Consumed / Unused / All.
      5. Columns include numeric code, deviceId, userId (owner), sessionId, expiresAt, consumedAt. In Actions, Device → /devices?deviceId=…; User → /users?userId=… when an owner is known; Session → /sessions?sessionId=… (1.40.0, when the row has sessionId; Sessions filter syncs to ?sessionId= in the URL).
      6. To change code length or TTL, use System pairing policy; hosts still generate codes on the Agent.
      7. 1.44.0 — Page header Create audit / Join audit open /audit?action=pairing.create or pairing.join (same presets as the Audit action filter since 1.43.0).

      #User drawer and cross-module links (1.38.0 / 1.42.0)

      1. Users — In the detail drawer, View sessions / recordings / pairings / orders / devices / audit deep-link to /sessions?userId=…, /recordings?userId=…, /pairings?userId=… (1.42.0; Pairings list filters by device owner substring), /orders?userId=…, /devices?ownerId=…, and /audit?actorId=… (devices list filters by ownerId; the drawer device tab still uses owner / org logic).
      2. Devices — When a row has an active session (correlated with in-memory rooms), Actions shows Monitor wall → /monitor-wall?s0=<sessionId> (slot 0 seed; not SFU multi-stream shipped).
      3. Sessions — Filter by user ID; filters sync to ?userId= in the URL (the user drawer View sessions button seeds this param). Client-side filter matches row userId (rows without userId do not match).

      #Membership and orders (1.42.0 / 1.43.0 / 1.52.0)

      1. Checkout — Web Client /membership (current viewer Admin has no Membership route): providerHint, QR/redirect, status polling after pay, and Complete payment (complete). Sandbox copy is not production PSP.
      2. Orders — Admin Orders lists local rows; Simulate paid is local_billing pending only. Read commerce together with Client Membership. Historical Admin Membership↔Orders deep-links are unrouted in the current viewer.
      3. Grant — If a trial user is stuck on Free, prefer Users → change plan; do not simulate-pay commerce orders.

      #Enterprise enablement & contract scope

      These capabilities are under Enterprise Fleet / contract scope (see Device Fleet & Enterprise) and are delivered per enablement and contract:

      • An editable permission matrix (the Permissions page is a read-only reference; role enablement is configured during rollout)
      • Larger-slot / multi-screen monitor wall scale (default in-wall observe; add-ons in the Fleet guide)
      • A correlation engine or alert DSL (alert rules lite is banner threshold + mute types)
      • Production WeChat Pay / Alipay secrets (never commit them; configure via Entitlement / environment)

      Engineering readiness: Implementation status.

      #Security

      • Prefer VPN or a private network for the admin URL; MFA is planned (P1).
      • Audit sensitive actions (disable user, plan changes, force disconnect, device revoke); filter and export CSV as needed.

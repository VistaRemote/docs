      #CI/CD and versioning

      VistaRemote uses per-repository builds and releases: each sub-repo has its own SemVer tags and GitHub Actions workflows. When @vistaremote/shared is published, downstream repos are notified to bump their dependency.

      Full normative spec: Meta-Repo spec/cicd-release-spec.md

      #Version and tag conventions

      RepoTag formatExampleArtifact
      sharedvMAJOR.MINOR.PATCHv0.2.0npm @vistaremote/shared (GitHub Packages)
      serverserver-v*server-v0.2.0Docker ghcr.io/vistaremote/server
      aiai-v*ai-v0.2.0Docker ghcr.io/vistaremote/ai
      webweb-v*web-v0.2.0Static artifacts (client + admin)
      desktopdesktop-v*desktop-v0.2.0Build artifact (installers P1)
      docsdocs-v*docs-v0.2.0GitHub Pages
      deploydeploy-v*deploy-v0.2.0Compose validation / release notes
      mobilemobile-v*mobile-v0.2.0Build verification (stores P1)
      downloads (public)v*v1.0.0Windows Agent + Android APK (anonymous download)

      Tags are the source of truth for releases; keep package.json#version aligned when possible.

      #End-user installers (public bucket)

      desktop / mobile source may stay private. User-facing binaries are published to the public repo VistaRemote/downloads. The marketing site /download page defaults to that repo’s releases/latest/download.

      From the Meta-Repo:

      pnpm pack:publish          # pack:all + upload to VistaRemote/downloads Release
pnpm publish:downloads     # upload existing artifacts only

      Requires gh auth login and matching desktop / mobile package versions. Prefer building the Windows Agent on Windows or via the desktop Actions workflow (windows-latest); Android APK can be built on macOS with pnpm pack:mobile.

      Website defaults:

      • NEXT_PUBLIC_RELEASE_BASE=https://github.com/VistaRemote/downloads/releases/latest/download
      • NEXT_PUBLIC_RELEASE_VERSION=1.0.0 (must match asset filenames)

      #Recommended release order

      1. Merge shared to main
2. Tag v0.2.0 → release.yml publishes npm package
3. repository_dispatch → consumer sync-shared.yml opens PRs
4. Merge bump PRs, tag server-v0.2.0 / web-v0.2.0 / …
5. Update deploy compose image tags → deploy-v0.2.0

      #Publish shared

      cd shared
git tag v0.2.0
git push origin v0.2.0

      Workflow shared/.github/workflows/release.yml: lint → test → build → publish → notify consumers.

      #Consumer auto-bump

      sync-shared.yml on each consumer:

      • Sets @vistaremote/shared to ^0.2.0
      • Runs install, lint, test, build
      • Opens PR: chore(deps): bump @vistaremote/shared to 0.2.0

      #Release services

      cd server
git tag server-v0.2.0
git push origin server-v0.2.0

      node tooling/scripts/restore-shared-file-deps.mjs

      WorkflowTriggerPurpose

      sync-shared.ymlshared-publishedAuto bump + PR
      release.ymltagImages / static site / npm
      dependency-review.ymlPRDependency review

      Meta-Repo meta-ci.yml only checks scaffolding, not sub-repo app code.

      #Maintainer setup

      Secret on VistaRemote/shared: VISTAREMOTE_CI_PAT (repo + workflow) for cross-repo dispatch.

      Sync workflow templates from Meta-Repo root:

      node tooling/scripts/setup-github-workflows.mjs
